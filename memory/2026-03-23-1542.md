# Factor Quality Rubric（v1）

## 一、总原则
一个“高质量因子”不等于：
- 最近一次分高
- 30d/45d 好看
- 有很多近亲一起赢

一个“高质量因子”更接近于：
- **跨窗口不过度塌陷**
- **neutralized 后仍保留一定信息**
- **不是重复候选**
- **相对父因子/现有代表有新增信息**
- **可解释，知道它为什么有效**
- **知道它属于 stable alpha 还是 regime-sensitive exposure**

---

# 二、建议的评分维度
总分建议 **100 分**，分 6 个模块。

## 1) 跨窗口稳健性：30 分
这是最重要的一项。

### 评分逻辑
看因子在：
- 30d
- 45d
- 60d
- 90d
- 120d
- expanding

这些窗口中的表现连续性，而不是只看最佳窗口。

### 建议打分
- **26-30 分**：45d/60d 都稳，90d 以上也没有明显崩坏
- **18-25 分**：30d/45d 强，60d 变弱但没断崖
- **8-17 分**：只在 30d/45d 有效，60d 明显塌
- **0-7 分**：窗口一拉长就失效，或结果极不稳定

### 一票否决信号
如果：
- 45d 还行，但 60d raw / neutralized 同时明显转负
- survivor 直接掉到 0
- split fail count 明显恶化

那这个模块最多给 **12 分**，默认按 **regime-sensitive** 看。

---

## 2) Neutralized 质量：20 分
很多东西 raw 好看，不代表真有 alpha。

### 看什么
- neutralized `rank_ic_mean`
- neutralized spread
- neutralized 后是否仍保留方向一致性
- raw 强但 neutralized 一去就没，还是保留部分优势

### 建议打分
- **16-20 分**：neutralized 后仍有稳定正信息
- **10-15 分**：neutralized 后变弱但不至于失真
- **4-9 分**：raw 好看，但 neutralized 明显塌
- **0-3 分**：neutralized 长期差、方向都反了

### 解释建议
- raw 强、neutralized 弱：更像 **exposure**
- raw 和 neutralized 都还行：更像 **alpha-like**
- neutralized 反复转负：质量要谨慎

---

## 3) 新增信息 / 增量价值：20 分
这是 hybrid 最容易作假的地方。

### 核心问题
相对它的：
- 父因子
- 组成因子
- 当前前沿代表

它到底多提供了什么？

### 要求
至少比较：
- 对基础因子的提升幅度
- 提升是否只出现在短窗口
- 提升是否只存在于 raw，不存在于 neutralized
- 提升是否可复现，而不是一次巧合

### 建议打分
- **16-20 分**：相对父因子有明确、可复现增量
- **10-15 分**：有增量，但主要在短窗口或依赖环境
- **4-9 分**：增量很弱，像“两个旧信号叠加”
- **0-3 分**：几乎无新增信息，本质是重复候选

### 规则建议
如果一个 hybrid：
- 与父因子高度相关
- 只比父因子在单次短窗口略高一点
- 没有稳定新增信息

则这一项不应高于 **8 分**。

---

## 4) 去重后独立性：15 分
这是防止“一个信号换十个名字”骗分。

### 看什么
- `duplicate_of`
- `refinement_of`
- 高相关候选簇
- 与已有 frontier representative 的差异度

### 建议打分
- **13-15 分**：明显独立，非重复，保留有意义
- **8-12 分**：有相关性，但还能提供一些新增视角
- **3-7 分**：和现有代表高度接近，价值有限
- **0-2 分**：本质重复，应 suppress / demote

### 规则建议
如果候选已被识别为：
- 另一个核心代表的 duplicate
- 高相关近亲且无额外信息

那这一项直接 **≤3 分**。

---

## 5) Split 一致性 / 失败风险：10 分
不是只看均值，还要看它是不是靠少数 lucky split 撑起来。

### 看什么
- split fail count
- 不同 split 的稳定程度
- 是否“均值不错，但离散度很烂”

### 建议打分
- **8-10 分**：多数 split 方向一致，失败少
- **5-7 分**：有波动，但整体还能接受
- **2-4 分**：靠少数 split 拉高
- **0-1 分**：split 经常失败，不可信

---

## 6) 可解释性 / 归因清晰度：5 分
这项分值不高，但很重要。

### 看什么
- 能否解释主要驱动
- 能否归类到明确 market regime
- 是 alpha-like 还是 exposure-like
- 是否能说明适用边界

### 建议打分
- **5 分**：驱动清楚，边界清楚
- **3-4 分**：大致能解释
- **1-2 分**：说不清楚为什么有效
- **0 分**：完全黑箱 + 不稳定

# 3）各模块打分函数

## A. 跨窗口稳健性（30分）

```python
def score_cross_window(candidate):
    m = candidate["metrics"]

    active_windows = 0
    medium_windows_ok = 0
    severe_break = False

    for w in ["30d", "45d", "60d", "90d", "120d", "expanding"]:
        if m[w]["raw_ic"] > 0 and m[w]["raw_spread"] > 0:
            active_windows += 1

    for w in ["60d", "90d", "120d", "expanding"]:
        if m[w]["raw_ic"] > 0 and m[w]["neu_ic"] > -0.01:
            medium_windows_ok += 1

    if (
        m["45d"]["raw_ic"] > 0
        and m["60d"]["raw_ic"] <= 0
        and m["60d"]["neu_ic"] <= 0
        and m["60d"]["survivors"] == 0
    ):
        severe_break = True

    if severe_break:
        return min(12, 6 + active_windows)

    if medium_windows_ok >= 3:
        return 26 + min(4, active_windows - 3)

    if m["30d"]["raw_ic"] > 0 and m["45d"]["raw_ic"] > 0 and m["60d"]["raw_ic"] > 0:
        return 18 + min(7, medium_windows_ok + 2)

    if m["30d"]["raw_ic"] > 0 and m["45d"]["raw_ic"] > 0:
        return 8 + min(9, active_windows)

    return min(7, active_windows * 2)
```

### 设计意图
- **最奖励跨到 60d+ 还活着的因子**
- **45d 好、60d 直接死** 的，直接压分
- 不让 30d/45d 的漂亮结果骗太多分

## B. Neutralized 质量（20分）

```python
def score_neutralized(candidate):
    m = candidate["metrics"]

    vals = [m[w]["neu_ic"] for w in ["30d", "45d", "60d", "90d", "120d", "expanding"]]
    pos_count = sum(1 for x in vals if x > 0)
    strong_neg_count = sum(1 for x in vals if x < -0.01)

    avg_neu = sum(vals) / len(vals)

    if avg_neu > 0.01 and pos_count >= 4:
        return 16 + min(4, pos_count - 4)

    if avg_neu > 0 and pos_count >= 3:
        return 10 + min(5, pos_count - 3)

    if strong_neg_count >= 3:
        return max(0, 3 - strong_neg_count)

    return 4 + max(0, pos_count - 1)
```

### 设计意图
- raw 强但 neutralized 很差的，不能拿高分
- 如果 neutralized 在多个窗口都保留正信息，才算真质量

def score_incremental(candidate):

    vs_parents = inc.get("vs_parents", 0.0)

def compute_hard_flags(candidate):
    m = candidate["metrics"]
    d = candidate["dedupe"]

    failed_60d = (
        m["60d"]["raw_ic"] <= 0
        and m["60d"]["neu_ic"] <= 0
        and m["60d"]["survivors"] == 0
    )

    neutralized_weak = sum(
        1 for w in ["30d", "45d", "60d", "90d", "120d", "expanding"]
        if m[w]["neu_ic"] < 0
    ) >= 3

    duplicate_risk = (
        d["duplicate_of"] is not None
        or (not d.get("has_unique_information", False))
    )

    untrusted_runs = not candidate.get("trusted_runs_only", False)

    return {
        "failed_60d": failed_60d,
        "neutralized_weak": neutralized_weak,
        "duplicate_risk": duplicate_risk,
        "untrusted_runs": untrusted_runs
    }

# 5）分类逻辑

```python
def classify_candidate(total_score, hard_flags, candidate):
    if hard_flags["untrusted_runs"]:
        return "validate-only"

    if hard_flags["duplicate_risk"]:
        return "duplicate-suppress"

    if hard_flags["failed_60d"]:
        if candidate["interpretation"].get("type") == "exposure-like":
            return "exposure-track"
        return "regime-sensitive"

    if total_score >= 85:
        return "stable-alpha-candidate"
    if total_score >= 70:
        return "needs-validation"
    if total_score >= 50:
        return "exposure-track"
    if total_score >= 30:
        return "validate-only"
    return "drop"
```

def decide_promotion(total_score, hard_flags, classification):

        return "hold"

    if hard_flags["duplicate_risk"]:
        return "suppress"

    if hard_flags["failed_60d"]:
        return "do_not_promote"

    if hard_flags["neutralized_weak"] and classification != "exposure-track":
        return "do_not_promote"

    if classification == "stable-alpha-candidate":
        return "promote"
    if classification == "needs-validation":
        return "keep_validating"

    return "do_not_promote"

# 一、背景与问题定义

## 1. 当前现状
目前 Factor Lab 已经证明：
- 不是完全没有信号；
- 前沿/研究选择路线，相比 legacy baseline，**有一定边际优势**；
- 但优势主要集中在 **30d/45d**；
- 一旦拉到 **60d/90d/120d**，大多数近期“赢家”就开始失效；
- 因子质量更多体现为**近期 regime 下的机会性信号**，而不是中窗口稳健 alpha。

## 2. 主要问题
当前因子质量提升的瓶颈，不是“候选太少”，而是：

### （1）短窗口幻觉偏多
很多候选在 30d/45d 表现不错，但到 60d 就明显失真甚至归零。

### （2）重复候选污染判断
多个高相关 hybrid 容易制造“发现很多赢家”的错觉，但本质上可能只是同一类信号的不同写法。

### （3）promotion 过于容易被短期分数驱动
如果晋升逻辑过度依赖 latest score 或短窗口表现，就会把脆弱因子误判为高质量因子。

### （4）raw 表现与 neutralized 表现存在偏差
有些候选 raw 好看，但 neutralized 后明显变差，说明其信息中混入了较多暴露成分。

### （5）研究资源分配不够聚焦
如果继续广撒网扩候选池，容易在低质量变体上消耗算力和注意力，而不是集中打磨真正的前沿代表。

---

# 二、总体目标

本计划书的核心目标不是“让更多因子看起来赢”，而是：

## 总目标
建立一套**高质量因子筛选、验证、分类、晋升机制**，让系统更擅长：

- 识别短窗口有效但不稳定的候选；
- 识别真正具备跨窗口延展性的候选；
- 区分 `stable alpha` 与 `exposure/regime signal`；
- 去掉重复和伪增量；
- 把研究资源集中到少数最值得验证的代表因子上。

---

# 三、阶段性目标

## 第一阶段：先把“质量定义”改对
目标：不再把“最近一次分高”当成“高质量”。

需要建立新的质量标准：
- 跨窗口稳健性；
- neutralized 保留度；
- 相对父因子的新增信息；
- 去重后独立性；
- split 一致性；
- 可解释性。

---

## 第二阶段：聚焦验证当前前沿代表
目标：不再广撒网，先把当前最值得盯的代表因子验证清楚。

当前优先对象：
- `hybrid_liquidity_turnover_shock_mom_20`
- `hybrid_mom_20_value_ep`
- `hybrid_size_small_value_bp`

---

## 第三阶段：把验证结果接入 promotion 机制
目标：让晋升逻辑自动反映“高质量因子”的真实标准，而不是继续奖励短窗口幻觉。

---

# 四、核心策略

## 策略 1：抬高晋升门槛
### 核心原则
一个因子想进入高等级池，不能只靠：
- 30d/45d 好看；
- 最新一次 run 分高；
- 多个近亲一起上榜。

### 新门槛建议
候选若想晋升，至少要满足：
- 60d 不明显崩；
- neutralized 不持续偏弱；
- 非 duplicate / refinement 噪声；
- 相对父因子有新增信息；
- 使用可信 run 结果；
- 能被解释为 alpha-like 或 exposure-like，而不是黑箱偶然结果。

### 预期作用
- 降低假阳性晋升；
- 提高 stable pool 的可信度；
- 让“少而真”的因子留下来。

---

## 策略 2：从“扩候选”转为“打磨代表因子”
### 核心原则
现阶段继续扩大量候选，收益已经低于继续验证当前代表。

### 执行方式
只保留每一类候选中的代表因子，围绕代表做：
- 45d vs 60d 断点验证；
- regime 解释；
- 父因子增量检验；
- 去重后排序；
- classification 决策。

### 预期作用
- 提升研究效率；
- 降低重复验证浪费；
- 更快看清哪些东西是真的。

---

## 策略 3：引入“增量价值”作为必查项
### 核心问题
每个 hybrid 必须回答：
> 它相比父因子，到底新增了什么？

### 必查内容
- 对父因子的提升是否显著；
- 提升是否跨窗口成立；
- 提升是否只存在于 raw；
- 提升是否只是近期风格共振。

### 预期作用
- 防止“换壳组合”虚假升格；
- 提高真正有新信息的因子比例。

---

## 策略 4：明确区分 alpha 与 exposure
### 核心原则
不是所有有效候选都该争取晋升成 stable alpha。

### 分类建议
所有候选最后都归入以下之一：
- `stable-alpha-candidate`
- `needs-validation`
- `exposure-track`
- `regime-sensitive`
- `duplicate-suppress`
- `drop`

### 预期作用
- 减少“把机会型信号误当长期因子”的错误；
- 让 Exposure Track 更有价值，而不是被当次级垃圾桶。

---

## 策略 5：优先研究“失效点”
### 核心原则
提高质量最有效的方法，不是再跑更多新因子，而是搞清楚已有因子为什么失效。

### 当前最重要的失效点
- `45d -> 60d` 的断点；
- raw 与 neutralized 的断裂；
- 代表因子与父因子的增量是否消失；
- 是否只是近期 market regime 支撑。

### 预期作用
- 更快定位质量天花板；
- 更早淘汰假信号；
- 避免无效算力消耗。

---

- 跨窗口稳健性（30）
- neutralized 质量（20）
- 增量价值（20）
- 去重后独立性（15）

- 60d raw + neutralized 同时失败且 survivor=0 -> 不得升 stable

### 任务 3：定义 classification 规则

- total_score
- hard_flags
- classification
- promotion_decision

### 验收标准
- 能形成统一 scorecard 输出结构；
- 系统能对候选给出“分数 + 分类 + 晋升建议”；
- 不再只看 latest_final_score。

## 第二部分：前沿代表专项验证
**时间：第 2-4 天**

### 任务对象

- `hybrid_liquidity_turnover_shock_mom_20`
- `hybrid_mom_20_value_ep`
- `hybrid_size_small_value_bp`

### 任务 1：45d / 60d 断点复核

- 45d rolling back
- 60d rolling back

提取：

### 目标

### 任务 2：regime / exposure 解释

### 目标

- 还是只是旧信号叠加。

### 验收标准
- 每个代表因子都能给出一页内的质量结论；
- 能明确 decide：`observe / exposure-track / drop`。

## 第三部分：去重与前沿池重构
**时间：第 4-5 天**

### 任务 1：整理高相关候选簇

- 高相关 cluster

### 任务 2：确立唯一代表
每一簇只保留：
- 一个 core representative
- 少量 validate-only 候选

### 任务 3：更新 research planning
让研究资源优先指向：
- 真正有新增信息的唯一代表；
- 而不是按历史候选数量扩散。

### 验收标准
- frontier 名单缩短但更干净；
- 近亲候选不再重复占据研究预算；

# 六、资源分配建议

## 1. 算力优先级
优先用于：
- 45d/60d 验证；
- corrected medium-horizon rerun；
- 增量检验；
- 去重后代表验证。

不优先用于：
- 大规模扩新候选；
- 大量高相关 hybrid 扩散；
- 低质量重复回测。

## 2. 人工注意力优先级
优先看：
- 60d 是否崩；
- neutralized 是否保留；
- 是否真的有新增信息；
- 是否能解释。

不优先看：
- 单次高分；
- 只在 30d 高光的临时冠军；
- 重复候选的微小排序差。

# 七、风险与应对

## 风险 1：过度收紧导致错杀
### 风险
门槛抬太快，可能把一些“还在成长中的候选”提前压掉。

### 应对
保留 `needs-validation` / `regime-sensitive` 层，不直接二元化。

---

## 风险 2：Exposure Track 被误判为低质量垃圾
### 风险
有些候选虽然不稳，但对轮动/暴露解释有真实价值。

### 应对
明确区分：
- stable alpha
- exposure-track
- regime-sensitive

不要只按一个总分粗暴淘汰。

---

## 风险 3：历史污染结果继续误导
### 风险
如果旧的 bug run、cache 污染 run、A/B harness 污染 run 被继续纳入，会扭曲结论。

### 应对
只允许可信 run 进入 promotion 与质量评估。

# 二、第一阶段任务拆解

## 任务 1：定义质量评分框架
### 目标
建立统一的因子质量评分 rubric，替代单纯依赖 latest score 的粗判断。

### 要做的事
确定评分维度与权重，建议先用这 6 个模块：

- **跨窗口稳健性**（30）
- **neutralized 质量**（20）
- **增量价值**（20）
- **去重后独立性**（15）
- **split 一致性**（10）
- **可解释性**（5）

### 具体要求
每个维度都要明确：
- 看哪些输入字段
- 高分条件是什么
- 低分条件是什么
- 有没有“一票压分”情形

### 预期产出
- 一份书面的 `Factor Quality Rubric v1`
- 每个维度的打分说明
- 每个维度对应的字段来源说明

### 验收标准
- 不看 latest score，也能解释一个候选为什么高/低质量
- 不同人按这个规则看，结论大体一致
- 可以映射为程序里的打分函数

---

## 任务 2：定义硬门槛规则
### 目标
防止某些候选虽然总分还行，但存在致命缺陷，仍被误晋升。

### 要做的事
定义几条**硬规则**，优先建议先落这几条：

#### 规则 A：60d 失败限制
如果候选在可信 run 中：
- 60d raw 失败
- 60d neutralized 失败
- survivors = 0

则：
- 不得升 stable
- 最多归类为 `regime-sensitive` 或 `exposure-track`

#### 规则 B：重复候选限制
如果候选属于：
- `duplicate_of`
- `refinement_of`
- 高相关且无新增信息

则：
- 不得独立记功
- 不得因“多个近亲一起赢”而抬高晋升概率

#### 规则 C：neutralized 风险限制
如果候选：
- raw 很强
- 但 neutralized 长期偏弱或转负

则：
- 不能当 stable alpha
- 最多归入 exposure 类

#### 规则 D：可信 run 限制
以下结果不能进入晋升判断：
- 受 bug 污染的 run
- A/B harness 污染 run
- 缓存污染 run
- 输入不可复现 run

### 预期产出
- 一份 `hard_flags` 定义文档
- 每个 flag 的触发条件和后果

### 验收标准
- 即使候选总分不低，只要触发硬门槛，也能阻止误晋升
- 能明显减少“短窗口漂亮但本质脆弱”的误判

---

## 任务 3：定义分类体系
### 目标
不再把所有“有效候选”混成一类，而是明确它到底属于什么。

### 要做的事
建立 classification 体系，建议先用：

- `stable-alpha-candidate`
- `needs-validation`
- `exposure-track`
- `regime-sensitive`
- `duplicate-suppress`
- `drop`

### 具体要求
为每个分类定义：
- 适用条件
- 典型特征
- 能否晋升
- 是否继续投入研究资源

### 分类建议逻辑
- **stable-alpha-candidate**：跨窗口较稳、neutralized 不差、非重复、有增量
- **needs-validation**：有价值，但证据不够
- **exposure-track**：有效但更像风格/暴露信号
- **regime-sensitive**：明显依赖近期环境
- **duplicate-suppress**：重复候选，不单独对待
- **drop**：质量低或被可信 run 否定

### 预期产出
- 一份分类说明文档
- 每个候选最终都能归到某一类

### 验收标准
- 看到一个候选，系统不仅能给分，还能给“身份判断”
- alpha / exposure / noise 三者不再混淆

---

## 任务 4：定义晋升决策逻辑
### 目标
把“打分”和“是否晋升”分开，避免简单按总分拍板。

### 要做的事
定义 promotion decision，建议先包含：

- `promote`
- `keep_validating`
- `do_not_promote`
- `suppress`
- `hold`

### 决策原则
- 总分高 + 无硬门槛 + 非重复 + 可信 run → 才能 `promote`
- 有价值但证据不足 → `keep_validating`
- 60d fail / neutralized 弱 / 重复 → `do_not_promote`
- 重复候选 → `suppress`
- 结果来源不可信 → `hold`

### 预期产出
- 一份 promotion 逻辑定义
- 从分数到动作的映射规则

### 验收标准
- promotion 不再是“谁最新分高谁上”
- 结果更符合“质量优先”而非“热度优先”

---

## 任务 5：设计 scorecard 输出结构
### 目标

# 五、第一阶段验收标准

第一阶段完成，不看“是否发现了更强因子”，只看规则体系是否建成。

### 验收通过的标志
- 能对任一候选输出“分数 + flags + classification + promotion_decision”
- 能解释为什么一个短窗口赢家不能升 stable
- 能识别重复候选，不再重复记功
- 能把 raw 强但 neutralized 弱的候选归到 exposure/regime-sensitive
- 能为第二阶段的代表因子专项验证提供统一判断框架

### 验收不通过的表现
- 还在主要看 latest score
- 还不能区分 alpha 与 exposure
- 还不能阻止重复候选抬高结论
- 还没有统一输出结构
