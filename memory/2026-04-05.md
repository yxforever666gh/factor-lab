Current project-state conclusions surfaced to the user:
- Recent factor quality is still only moderate/fragile overall.
- Value-line factors show some raw signal but often fail neutralized spread or multi-window robustness.
- Momentum line remains weak and drags many hybrid branches down.
- Current system was spending too much effort on repeated variants within the same clusters/families instead of producing stronger orthogonal hypotheses.

Code/runtime changes implemented during this session:
1) Quality-priority throttling for candidate generation and candidate-pool planning
- Added a quality-priority mode that detects missing frontier evidence, duplicate pressure, and diagnosis-heavy conditions.
- When quality priority is active, generated-candidate creation is throttled or fully suppressed, exploration is deprioritized, and runtime budget shifts back toward validation.
- This behavior was wired into `candidate_generator`, `research_candidate_pool`, and `research_metrics`.

2) Promotion/evidence gating tightened
- `promotion_scorecard` now reads the candidate risk profile’s `acceptance_gate`/evidence state and treats missing or blocked evidence as a hard promotion constraint.
- High-scoring but evidence-incomplete candidates now classify as validation-only / hold instead of being allowed to masquerade as strong promotable factors.

3) Operator learning made stricter
- Repeated operator outcomes with no gains and repeated high-value failures now downweight the relevant operator/family-operator path more aggressively instead of leaving it in a soft neutral state.
- This was implemented in `research_learning` and covered by tests.

4) Family-gap generation added
- Candidate generation no longer only expands from stable+graveyard or high-value-failure seeds.
- Added a `family_gap` route so the runtime can deliberately branch into underrepresented / lower-duplication families rather than continuing to recombine the same crowded momentum/value cluster.
- `candidate_generation_policy.json` was updated with `family_gap` operator preferences favoring more conservative differentiation operators like residualize/orthogonalize/combine_sub.

5) Dashboard visibility improved
- Dashboard was updated to surface quality-priority state / evidence-gap pressure / duplicate pressure / candidate-generation budget so the user can see why runtime behavior is validation-heavy or exploration-light.

Testing outcome:
- Multiple targeted test batches were run during the session and passed after fixes.
- New/updated tests now cover: quality-priority throttling, promotion hold on missing evidence, stricter operator downweighting, family-gap candidate generation, and related governance/metrics behavior.

Durable product direction learned:
- User currently prefers concrete implementation over more abstract planning once a direction is agreed.
- The right next phase is to keep converting the system from an exploratory hypothesis generator into a stricter quality filter: stronger evidence gates, cluster/family throttling, planner scoring that explicitly penalizes incomplete evidence and repeated duplicate pressure.
