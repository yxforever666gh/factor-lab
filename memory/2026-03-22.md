# 2026-03-22

- Factor Lab project direction clarified: the user accepts **Exposure Track** outputs (style/industry rotation factors) rather than requiring pure neutralized alpha. For this track, the preference is **strength-first** (higher IC/Sharpe is preferred even with more volatility) as long as risk is interpretable and controllable.
- Latest-run semantics were standardized across the project to mean the **latest finished workflow run ordered by `created_at_utc DESC`** for WebUI / LLM snapshot / latest summary. Daemon `last_processed` selection was also fixed to use the most recently processed task.
- Added an initial **Exposure Track** implementation to Factor Lab: DB table/view support, pipeline refresh, WebUI dashboard section, and `/exposure` page for strength-first exposure factors.
- Research daemon debugging uncovered multiple operational issues and partial fixes:
  - recovery fallback tasks were being blocked by fingerprint dedupe, causing empty-queue idle loops;
  - recovery deadlock fuse was added to force expansion/reseed after repeated zero-injection recovery loops;
  - stale `running` research tasks can block orchestration, so stale-running cleanup was added;
  - naive timestamps in the DB caused offset-naive vs offset-aware datetime crashes, so runtime parsing now normalizes naive timestamps as UTC.
- User finds Factor Lab heartbeat/wake reminders noisy. Recommended approach is to keep OpenClaw heartbeat generally available but **silence or reduce Factor Lab-specific wake/reminder messages** rather than globally disabling heartbeat.
- OpenClaw Control UI chat page model dropdown comes from `ui/src/ui/app-render.helpers.ts` (`renderChatModelSelect` / `buildChatModelOptions`), with model data fed by `app-chat.ts` refresh/load logic. The dropdown should display `provider/model` refs and must not collapse distinct providers that share the same model id.
- While patching the installed `control-ui` bundle, I accidentally broke the generated JS around `q_()` / `switchChatModel`; the file was repaired and now passes `node --check` again.
- The “models disappeared” regression on the chat page came from a TDZ bug in the generated `ocResolveChatModelRef()` helper: an inner `let s = ...` shadowed the loop variable and caused `Cannot access 's' before initialization` during render. After patching the bundle and reloading the browser, the chat model select now shows `Default (...)` plus all three `provider/model` catalog entries.
